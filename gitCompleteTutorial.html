Git 完整協作流程教學

Fork → Clone → Branch → Commit → Push → Pull Request → Merge

基本概念 Fork Clone Branch Commit Push PR Merge 總結

📚 基本概念

🔱 Fork

把別人的 repo 完整複製一份到自己的帳號下，變成你自己的 repo。

🌿 Branch

從主線拉出一條獨立支線，在支線上改東西不會影響主線。

💾 Commit

把改動儲存成一個版本，每個 commit 都是一個可回溯的節點。

🔀 Pull Request

把改好的分支請求合併到主線，並讓別人 review 你的程式碼。

💡 為什麼需要這套流程？
模擬真實的開源協作。你不能隨便 push 到別人的 repo， 必須 fork 一份到自己那邊改，再發 PR 請求對方審核。 這個流程保護了主線的穩定性，也確保程式碼品質。

🔱 步驟 1：Fork（網頁操作）

1到老師的 repo 頁面

到 https://github.com/se-111410545/git-examples

2點右上角的 Fork 按鈕

GitHub 會問你要 fork 到哪裡，選擇你的帳號（或 organization）。

💡 為什麼？
Fork 後你擁有這個 repo，可以自由修改、push。否則你對老師的 repo 只有唯讀權限。

3確認 Fork 成功

檢查網址列，應該變成 https://github.com/你的帳號/git-examples

📥 步驟 2：Clone（複製到本地）

1複製你 fork 的 repo

git clone git@github.com:你的帳號/git-examples.git
cd git-examples
💡 為什麼 clone 自己 fork 的，不是老師的？
你有老師 repo 的 push 權限，但你有自己 fork 的 push 權限。 Clone 哪個就代表你是用哪個身份。

2設定 upstream（選配但建議）

git remote add upstream git@github.com:se-111410545/git-examples.git
git remote -v
💡 為什麼？
origin = 你的 fork（你推送的地方）
upstream = 老師的原始 repo（同步用的參考） 之後要抓老師的最新改動：git fetch upstream

🌿 步驟 3：Branch（開分支）

1確認目前在 main

git branch
git pull

2建立並切換到新分支

git checkout -b feature/my-work
💡 為什麼要開分支？
不直接在 main 改，才不會： 1. 污染主分支，害到任何人都能跑 2. 改到一半壞掉，影響別人 3. 沒法同時辦不同功能
分支就像實驗室，寫壞了刪掉就好，main 永遠穩定。

💾 步驟 4：Commit（提交改動）

1修改檔案

在本地新增、修改、刪除檔案。

2查看改動

git status         # 看改了哪些檔案
git diff           # 看具體改了什麼

3加入暫存區

git add gitBranch.md
git add .          # 全部加入（慎用）
💡 為什麼要 add？
add 決定這次 commit 要包含哪些檔案。 避免不小心 commit 進測試檔、私人設定、密碼檔。

4建立 commit

git commit -m "Add gitBranch.md - Git Branch 教學"
💡 為什麼要有 commit？
每個 commit 是一個可回溯的歷史節點。 未來可以 checkout 到任意 commit、看出誰改了什麼、出問題可以 revert。

🚀 步驟 5：Push（推送到遠端）

1第一次推送

git push -u origin feature/my-work
💡 -u 是什麼？
-u = --set-upstream，設定上游關聯。 設定後只需打 git push 就會自動推到正確分支。

2之後推送

git push

已經設定 upstream 後就只需打 git push。

🔀 步驟 6：Pull Request（發 PR）

1到 GitHub 你的 repo 頁面

推送完成後，GitHub 通常會顯示一個黃色橫幅："Compare & pull request"，直接點下去。

或手動切換到 feature 分支，按上方 Pull request → New pull request。

2設定 PR 方向

  • base repository（合併進）：選老師（或目標）的 repo + main
  • compare branch（你的改動）：選你的 feature/my-work

3填寫 PR 內容並送出

標題：簡單一句話描述
內容：說明改了什麼、為什麼要改、怎麼測試
💡 為什麼要 PR？
1. Code Review：讓別人看過你的程式碼，減少 bug
2. 紀錄：留下為什麼這樣改的脈絡
3. 討論：可以針對程式碼留言、提問、修改
4. 保護主線：main 只能收經過審查的程式碼

✅ 步驟 7：Merge（合併）

1審查 PR

PR 發出後，目標 repo 的擁有者（這裡是老師，或你自己另一個帳號）會收到通知。

審查者可以：

  • 看程式碼改動（diff）
  • 留言、提問、要求修改
  • 通過審查 → 按 Merge pull request

2按下 Merge

合併方式有三種：

  • Create a merge commit（預設）：保留所有 commit 歷史
  • Squash and merge：把多個 commit 合併成一個
  • Rebase and merge：線性歷史，看起來像從 main 直接開發

3合併完成後的本地操作

git checkout main
git pull                              # 抓回最新的 main
git branch -d feature/my-work         # 刪本地分支
git push origin --delete feature/my-work # 刪遠端分支

🎯 整個流程的意義

這個流程看起來繁瑣，但解決了三大問題：

  • 🛡️ 保護主線：main 永遠是穩定版本，不會被半成品污染
  • 👥 多人協作：每個人在自己的分支做，最後由 PR 整合
  • 🔍 程式碼品質：透過 PR 讓別人 review，降低 bug 機率

一句話濃縮：

Fork 複製 → Clone 下來 → 開分支開發 → Commit 存檔 → Push 上傳 → 發 PR 請求合併 → Merge 進主線。 整個過程中 main 不會被污染，所有改動都有跡可循。
