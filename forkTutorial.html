Git Fork 完整教學

理解 Fork 的意義、上下游關係、與完整實作流程

什麼是 Fork 為什麼要 Fork 上下游 完整流程 同步 upstream 發 PR 常見問題

🔱 什麼是 Fork？

Fork 就是「把別人的 repo 完整複製一份到自己的帳號下」。 複製後的 repo 是你的，你可以自由修改、push，不會影響原作者的 repo。

💡 簡單比喻：
Fork 就像「影印別人的書」，影印本是你的，你可以在上面寫筆記、畫螢光筆， 但不會影響到原版的書。如果你的筆記很好，想讓原作者收進新版本， 就可以「發 Pull Request」請求原作者把你的改動合併回去。

🤔 為什麼需要 Fork？

1你沒有 push 權限

在 GitHub 上，除非你是 collaborator，否則你無法直接 push 到別人的 repo。

Fork 後你擁有自己那份的完整權限，可以自由修改。

2保護原作者的程式碼

如果人人都能改 main，那專案會馬上壞掉。Fork + PR 確保所有 merge 都經過審查。

3模擬真實開源貢獻

外面的開源專案（Linux、React、Vue...）都是用 Fork + PR 流程運作。 學會這個你就會參與任何開源專案了。

🔗 上下游關係（origin vs upstream）

1origin（你的 fork）

你 git push 推送的地方。Clone 時自動設定的預設遠端。

git clone git@github.com:NaroFeng/git-examples.git
# 自動設定 origin = NaroFeng/git-examples

2upstream（原作者的 repo）

原作者的 repo，用來「同步最新改動」跟「發 PR 回去」。需要手動加入。

git remote add upstream git@github.com:se-111410545/git-examples.git
git remote -v
# origin    NaroFeng/git-examples.git (fetch)
# upstream  se-111410545/git-examples.git (fetch)
💡 為什麼要分兩個？
origin = 你寫程式的地方（隨便改）
upstream = 原作者的參考（只能 fetch 不能 push）
分開管理才不會把測試 commit 推到原作者那邊。

📋 完整流程

1Fork（網頁操作）

到原作者 repo，按右上角 Fork。

2Clone 你的 fork

git clone git@github.com:NaroFeng/git-examples.git my-fork
cd my-fork

3設定 upstream

git remote add upstream git@github.com:se-111410545/git-examples.git

4從 upstream 開新分支

git fetch upstream
git checkout -b feat/my-change upstream/main
💡 為什麼從 upstream 開？
如果從你的 main 開分支，會夾帶你 main 上多餘的 commit 進 PR。 從 upstream/main 開分支，PR 才會乾淨。

5修改、commit、push

# 修改檔案
git add .
git commit -m "說明做了什麼"
git push origin feat/my-change

6發 Pull Request

到 GitHub 你的 fork 頁面 → Compare & pull request → base 選 upstream，compare 選 feat/my-change。

7等待審查並 Merge

原作者（或自己另一個帳號）按 Merge pull request 完成合併。

🔄 同步 Upstream 最新改動

當原作者更新了 repo，你想抓回最新版本：

1抓取 upstream 最新

git fetch upstream

2切回 main 並合併

git checkout main
git merge upstream/main

3推回你的 fork

git push origin main
💡 為什麼要同步？
如果你 fork 後原作者又更新了，你的 PR 會「落後」於原作者的 main，GitHub 會警告。 先同步再發 PR，reviewer 才看到完整的最新狀態。

🔀 發 Pull Request 詳細步驟

1推送分支後到 GitHub

push 完成後到 https://github.com/NaroFeng/git-examples，GitHub 通常會顯示提示橫幅。

2點 Compare & pull request

或手動切換到分支，按上方 Pull Request → New pull request。

3設定 base 與 compare

  • base repository：原作者的 repo + main（合併進去的地方）
  • compare branch：你的 fork + feat/my-change（你的改動）

4填寫 PR 內容

標題：簡短描述
內容：
- 為什麼改
- 改了什麼
- 如何測試
- 相關 issue 編號（如果有）

5送出

按 Create pull request。完成後到原作者 repo 頁面會看到你的 PR。

❓ 常見問題

Q: 為什麼 PR 顯示「out-of-date」？

你的 fork 缺少原作者最新的 commit。先 sync upstream 後再推一次分支即可。

git fetch upstream
git checkout feat/my-change
git rebase upstream/main
git push -f origin feat/my-change

Q: Fork 跟 Clone 有什麼差別？

Clone 是把 repo 複製到本地（唯讀就沒有 push 權限的 repo 也行）。

Fork 是把 repo 複製到自己帳號下（讓你獲得 push 權限）。

Q: Fork 會不會一直跟著原作者更新？

不會自動。要手動 git fetch upstream + git merge upstream/main。

Q: 發 PR 後還能繼續 commit 嗎？

可以！繼續 commit + push 到同一條分支，PR 會自動更新。

git commit -m "補充說明"
git push origin feat/my-change
# PR 自動看到新 commit

Q: 想撤回 PR 怎麼辦？

到 PR 頁面按 Close pull request 即可。分支跟 commit 都還在，只是 PR 關閉了。

🎯 總結

Fork 的精神是：

  • 🛡️ 隔離實驗空間: 隨便改、不怕影響原作者
  • 🤝 透過 PR 合作: 改完用 PR 請求合併，不是偷偷改 main
  • 🔄 持續同步: 透過 upstream 隨時抓原作者更新
  • 👥 模擬多人協作: 每個人 fork 一份，互不干擾

一句話濃縮：

Fork = 複製別人的 repo 到自己帳號。
Clone 自己 fork 來改 → 從 upstream 開新分支 → 改完 push → 發 PR 回去。
這就是開源世界運作的方式。
