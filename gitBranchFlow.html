Git Branch 流程複習

理解每一步在做什麼，以及為什麼要這樣做

📊 完整流程圖

🔍 每一步在做什麼？

1git checkout -b feature/git-branch-doc

從 main 拉出一條新分支，並切換過去。

💡 為什麼？
不直接在 main 上改，才不會污染主分支。萬一寫壞了，刪掉分支就好，不會影響其他人。 
git checkout -b feature/git-branch-doc

2編輯檔案（新增 gitBranch.md）

在新分支上自由修改、新增、刪除檔案。

💡 為什麼？
分支就像一條「實驗線」，所有測試都在這條線上做，main 保持穩定可運行的版本。

3git add . → git commit

把改動加入暫存區，並建立一個提交點。

git add .
git commit -m "Add gitBranch.md"
💡 為什麼？
add 決定「這次 commit 要包含哪些改動」，避免不小心把測試檔或私人設定 commit 進去。

4git push -u origin feature/git-branch-doc

把本地分支推上遠端。

git push -u origin feature/git-branch-doc
💡 為什麼？
-u 是設定上游追蹤，之後只要打 git push 就會自動推到同一條遠端分支。

5發 Pull Request（PR）

到 GitHub 上請求把 feature 分支合併回 main，並請別人審查。

💡 為什麼？
PR 是「程式碼審查 (Code Review)」的機制。讓別人在合併前看過你的程式碼，降低出錯機率。這在團隊協作中非常重要。

6Merge（合併）

審查通過後，把 feature 分支合併回 main。

git checkout main
git merge feature/git-branch-doc
git push
💡 為什麼？
main 永遠代表「目前可發布的版本」。只有經過審查的程式碼才能進入 main。

⚖️ 有 vs 沒有 Branch 的差別

❌ 不開分支（直接改 main）

  • 改一半壞掉，整個專案壞掉
  • 無法同時多人協作
  • 沒有 review，bug 直接上線
  • 出問題難以回溯

✅ 使用 Branch

  • main 永遠穩定可運作
  • 多人可平行開發不同功能
  • PR 機制確保品質
  • 出問題可隨時砍掉該分支

🎯 一句話總結

Branch = 獨立的工作空間。 開發新功能時永遠從 main 開新分支，commit 後發 PR，等審查通過再 merge 回 main。 這個流程保證了 main 永遠是穩定版，也讓團隊協作變得安全有序。
