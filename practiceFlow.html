📋 本次練習完整流程紀錄

Fork → Branch → Push → PR → Rebase → Merge 的真實操作經驗

整體流程圖

①Fork 老師的 repo

在 se-111410545/git-examples 頁面按 Fork，複製一份到 NaroFeng/git-examples。

💡 為什麼？
取得 repo 的完整 push 權限，否則你只能唯讀。

②Clone 自己的 fork

git clone git@github.com:NaroFeng/git-examples.git my-fork-examples
cd my-fork-examples
git remote add upstream git@github.com:se-111410545/git-examples.git
git remote -v
💡 為什麼要 clone fork 而不是老師的？
Clone 哪個代表你用哪個身份操作。Clone fork 才能 push。

③從 upstream 開新分支（關鍵！）

git fetch upstream
git checkout -b feat/fork-tutorial upstream/main
⚠️ 注意：從 upstream/main 開分支，不要從自己 fork 的 main 開。 否則 PR 會夾帶你 fork main 上多餘的 commit（像 myfork.md 那種個人紀錄）。

④新增檔案並 commit

git add forkTutorial.html forkExercise.md
git commit -m "Add forkTutorial.html and forkExercise.md - Fork 練習"

⑤Push 到自己的 fork

git push -u origin feat/fork-tutorial

-u 設定上游追蹤，之後只需 git push。

⑥到 GitHub 發 Pull Request

到 https://github.com/NaroFeng/git-examples → 按 Compare & pull request。

  • base repository: se-111410545/git-examples / main
  • compare branch: feat/fork-tutorial
⚠️ 這個時候 GitHub 可能會顯示「out-of-date」，因為 fork 缺少老師那邊後來加的檔案。 別慌張，繼續下一步。

⑦Rebase 到最新 upstream（解決 out-of-date）

git fetch upstream
git checkout feat/fork-tutorial
git rebase upstream/main
git push -f origin feat/fork-tutorial
💡 Rebase 在做什麼？
把你的 commit「重新接到」最新的 upstream main 上。 結果：feat 分支的歷史變乾淨，PR 也不會 out-of-date。
💡 為什麼 -f（force push）？
Rebase 後 commit 的 hash 會改變，遠端舊的 commit 已經不存在， 必須強制覆蓋才能推上去。只在自己的分支上用，別人的分支不能用 -f。

⑧Merge PR

回到 GitHub PR 頁面，按 Merge pull request 確認合併。

合併後 se-111410545 的 main 會多出 forkTutorial.html 和 forkExercise.md。

⑨Pull 回本地（另一個資料夾）

cd ../git-examples
git pull
💡 為什麼要 pull？
PR merge 後老師的 repo 已經有 forkTutorial.html 等新檔案。 Pull 下來讓本地也跟上最新狀態，這樣 index.html 才能正確索引到所有檔案。

⑩更新 index.html 並 push

git add index.html
git commit -m "Add index.html - Git 教學索引頁"
git push origin main
💡 為什麼 index.html 要包含 fork 教學連結？
因為 PR merge 後，那些檔案已經存在了。 index.html 作為入口頁，應該包含所有檔案的連結，方便瀏覽。

🔑 關鍵觀念整理

origin vs upstream

origin = 你自己的 fork（推送的地方）

upstream = 原作者的 repo（同步參考）

為什麼 PR 會 out-of-date？

Fork 是「快照」，原作者更新後 fork 不會自動同步。

解法：git fetch upstream + git rebase upstream/main

Rebase vs Merge 差別

Merge：保留分支歷史，產生 merge commit（會出現分岔再合流的圖形）

Rebase：線性乾淨，看起來像直接從 main 開發（適合 PR 前整理）

Force Push 的危險與安全

危險：覆蓋遠端歷史，可能把別人的 commit 刪掉

安全：只對自己 fork 的分支用，絕不在 main 或協作分支用

🎯 一句話總結這次練習

  • Fork 拿到 push 權限
  • 從 upstream 開分支，確保 PR 乾淨
  • Push + 發 PR，請求合併
  • Rebase 解決 out-of-date，把 fork 接到最新 upstream
  • Merge + Pull，把新檔案拉回來，更新 index
  • Push，最終所有檔案都在老師的 repo

這套流程完整模擬了真實開源貢獻的每一步： Fork → Branch → Commit → Push → PR → Rebase → Merge → Pull → Push
